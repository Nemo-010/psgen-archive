## Body

## What happens

`psgen doctor --json` emits `checks` as an array of single-key objects, so every
consumer has to unwrap an object per capability:

```json
{
  "version": "0.0.1",
  "ok": true,
  "env": { "uid": 966, "euid": 966, "mem_total_kb": 12131920, "cgroup_mem_limit_kb": 0,
           "page_kb": 4, "hz": 100, "cwd": "/workspace/qa/w" },
  "checks": [
    { "pty":        { "ok": false, "detail": "/dev/ptmx open failed", "errno": 2 } },
    { "memfd":      { "ok": true,  "detail": "memfd_create and ftruncate" } },
    { "proc_exe":   { "ok": true,  "detail": "/workspace/qa/bin/psgen" } },
    { "mount_ns":   { "ok": false, "detail": "unshare, uid map or MS_PRIVATE failed", "errno": 1 } },
    …
  ],
  "probe": { "cap_eff": "0000000000000000", "has_caps": "no", "seccomp_mode": "2", … },
  "pidfile": { "/tmp/p.pid": { "writable": false } }
}
```

Consequences:

* `jq -r '.checks[] | .name'` (the obvious thing) yields nothing; the workaround
  is `.checks[] | to_entries[] | …`, and every consumer has to know the name is
  a *key*, not a field.
* A single-key object is not what any JSON-schema-shaped consumer expects for a
  list of records, so `checks[].errno` cannot be filtered without `.[]`.
* `pidfile` has the same shape (`{ "<path>": { "writable": false } }`) — a path
  as a JSON key cannot be represented if it is not valid UTF-8, and `json_string`
  silently turns such bytes into `?`.

```
$ psgen doctor --json | jq '.checks[].name'         # null, null, null …
$ psgen doctor --json | jq -r '.checks[] | to_entries[] | "\(.key) \(.value.ok)"'
pty false
memfd true
…
```

(the expressions above were evaluated against the real document with Python's
`json` module here — `jq` is not installed in the test cage — and give
`[None, None, None, …]` for the first and `pty false` / `memfd true` for the
second, i.e. exactly what `jq` produces for an array of single-key objects.)

## Patch (verified)

```diff
--- a/src/doctor.rs
+++ b/src/doctor.rs
@@ -182,13 +182,12 @@
         for (i, c) in checks.iter().enumerate() {
             if i > 0 {
                 out.push(b',');
             }
             out.push(b'{');
-            json_string(&mut out, c.name.as_bytes());
-            out.push_str(":{\"ok\":");
+            out.push_str("\"name\":");
+            json_string(&mut out, c.name.as_bytes());
+            out.push_str(",\"ok\":");
             out.push_str(if c.ok { "true" } else { "false" });
             out.push_str(",\"detail\":");
             json_string(&mut out, &c.detail);
             if !c.ok {
                 out.push_str(",\"errno\":");
                 json_number(&mut out, c.errno.max(0) as u64);
             }
             out.push(b'}');
-            out.push(b'}');
         }
```

giving `"checks":[{"name":"pty","ok":false,"detail":"…","errno":2}, …]`.

`tests/invariants.py` reads the old shape and has to change with it — it is the
only consumer in the tree:

```diff
     by_name = {}
     for item in checks:
-        for name, body in item.items():
-            by_name[name] = body
+        by_name[item["name"]] = item
```

Verified: `jq '.checks[0]'` → `{"name":"pty","ok":false,…}`,
`jq '[.checks[]|select(.ok==false)|.name]'` → `["pty","mount_ns","bind_mount",
"user_switch","passwd"]`, and `tests/smoke.sh` passes with the test patch.

## While in there

* Document what `"ok"` means. Today it is `true` on a host where 5 of 11
  capabilities are `DENY`, because it only covers `proc_exe`, `fork` and
  `prctl_name` (`doctor.rs`, `let core = [...]`). That is a reasonable choice;
  the field name just does not say it. `"core_ok"` plus a documented list, or a
  README line, would end the guessing.
* `env` decides number-vs-string by "all bytes are ASCII digits", so a `cwd` of
  `/1234` would be emitted as a string but a `cwd` of `1234` as a number. Cheap
  fix: type each key explicitly (`uid`/`euid`/`mem_total_kb`/`cgroup_mem_limit_kb`/
  `page_kb`/`hz` are the numbers; `cwd` is a string).

## Environment

psgen 0.0.1-beta.1 x86_64-unknown-linux-musl, unprivileged, Linux 7.2.11,
the JSON expressions in this report were evaluated with Python's `json`
module against the real `doctor --json` document.
