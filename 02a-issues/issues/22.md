# Azathothas/psgen#22: A one-field pidfile line cannot stop a bind-tier or shadow-tier row, and stop reports success anyway

## Body

`stop` identifies a pidfile line by `/proc/PID/exe` when the line has only a PID. A bind-tier stub's exe is the template path (`/usr/sbin/nginx`) and a shadow-tier stub's is the shadow copy (`psgen-stub`), so a one-field line silently skips every row it names and `stop` reports success.

## What happens

```
$ psgen inject -n 2 -s 5 --pidfile /tmp/of.pid -q
$ awk '!/^#/{print $1}' /tmp/of.pid > /tmp/one.pid
$ cat /tmp/one.pid
3811
3812
$ psgen stop --pidfile /tmp/one.pid
stopped 0 processes, skipped 2
$ echo $?
0
$ for p in 3811 3812; do awk '{print $3}' /proc/$p/stat; done
S
S
$ psgen stop --pidfile /tmp/of.pid     # the three-field form works
stopped 2 processes
```

Both stubs are alive after a `stop` that reported rc 0. The three-field form
(`pid<TAB>starttime<TAB>comm`) does work, because it compares starttime and comm
rather than the exe link.

## Why

`src/inject.rs`, `stop()`:

```rust
let identity_matches = |pid: i32, fields: &[&[u8]]| -> bool {
    if fields.len() >= 2 {
        ...  // starttime and comm
    } else {
        // A one-field line carries no starttime, so the exe check
        // is the only identity guard. --force covers the boot id only.
        exe_matches(pid, &me)
    }
};
```

and `me` is `current_exe_bytes()` — the `psgen` binary running `stop`. For a
bind-tier row, `/proc/PID/exe` is the template path; for a shadow-tier row it is
`.psgen-stubs/.psgen-<pid>-9000-<n>/psgen-stub`. Neither equals the `psgen` binary,
so the comparison fails and the row is counted as `skipped`, which is not a failure
(`failed` stays 0, so the exit code is 0 and the temp dirs are removed).

`README.md` says the opposite:

> `stop --pidfile FILE` checks the boot id, then each line's identity before
> signalling: a three-field line checks starttime and comm, a two-field line
> checks starttime, and a one-field line checks the exe.

That is true only for proc-self rows, the one tier where the stub is the `psgen`
binary itself. The README does not say so.

## Why it is not a simple "accept more paths"

Accepting the template exe or the shadow copy would make a one-field line *less*
safe, not more: any process whose exe is the template path would then be a valid
target, including the real nginx on the host. That is exactly what the three-field
form exists to prevent.

## Options

1. **Document it** (smallest): say "a one-field line identifies proc-self rows only;
   bind and shadow rows need the three-field form". The `--help` is already correct
   after the report's patch (`a one-field line still requires an exe match (proc-self
   rows only)`); `README.md` needs the same qualifier.
2. **Refuse it**: if the run is not proc-self, a one-field line should be a hard
   error (`exit 2`, "a one-field pidfile cannot identify a bind-tier run"), not a
   silent skip that reports success. This is the behaviour that would have prevented
   the confusion.
3. **Remove the one-field form** and require three fields. It exists for
   hand-written pidfiles; there is no producer in the tool.

I would do 2 now and 1 as the doc fix, because the current state is the worst of
both: the form is accepted, does nothing, and reports success.

## Test that would have caught it

```python
pidfile, pids, _ = inject_and_check([...], tmp, 2)
one = Path(tmp) / "one.pid"
one.write_text("".join(f"{p}\n" for p in pids))
p = run(["stop", "--pidfile", str(one)], check=False)
if p.returncode == 0 and all(alive(p) for p in pids):
    fail("a one-field pidfile reported success without signalling anything")
stop_pidfile(pidfile)
```

## Environment

`bf80156` built with `cargo 1.99.1`, x86-64, Linux 7.2.11, unprivileged uid 966,
exe tier `shadow` (no mount namespaces here, so the bind tier is unavailable — but
the bind tier fails the same way, with the template path instead of the shadow copy).
Proc-self rows are the only tier where the current behaviour is correct.
