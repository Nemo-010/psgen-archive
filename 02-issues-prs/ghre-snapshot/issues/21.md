## Body

`psgen check --binaries` reports binaries as missing when the absolute path in the command line exists. `executable()` strips the directory from every command, and `exists()` only then searches five hardcoded directories, so anything outside `/usr/local/bin`, `/usr/bin`, `/bin`, `/usr/sbin` and `/sbin` is reported missing no matter what the corpus says.

## What happens

`/usr/lib/bluetooth/bluetoothd` exists on this host:

```
$ ls -l /usr/lib/bluetooth/bluetoothd
-rwxr-xr-x 1 65534 65534 1741296 Jul  5 17:29 /usr/lib/bluetooth/bluetoothd
$ psgen check --binaries | grep bluetooth
missing: bluetoothd  <- /usr/lib/bluetooth/bluetoothd
$ psgen check --binaries | grep -c '^missing:'
148
```

The command in the corpus is an absolute path that exists, and it is counted as
missing. The same happens for the systemd units, which live in `/usr/lib/systemd/`:

```
missing: systemd-journald  <- /usr/lib/systemd/systemd-journald
missing: systemd-udevd     <- /usr/lib/systemd/systemd-udevd
```

and for anything installed under `~/.cargo/bin`, `/usr/local/go/bin` or `/opt`,
which is why a `cargo` row is reported missing on a host where `cargo` is on `PATH`.

## Why

`src/check.rs`:

```rust
fn executable(cmd: &[u8]) -> Option<&[u8]> {
    ...
    let name = if let Some(rest) = first.strip_suffix(b":") {
        rest
    } else if let Some(p) = first.iter().position(|b| *b == b':') {
        &first[..p]
    } else {
        str::basename(first)          // <- the directory is discarded
    };
    ...
}

fn exists(name: &[u8]) -> bool {
    if name.contains(&b'/') {
        return sys::access(name, 1);
    }
    for dir in [&b"/usr/local/bin/"[..], &b"/usr/bin/"[..], &b"/bin/"[..],
                &b"/usr/sbin/"[..], &b"/sbin/"[..]] {
        ...
    }
    false
}
```

The `name.contains(&b'/')` branch in `exists()` is unreachable for the common case,
because `executable()` already reduced an absolute path to its basename. The one
thing the command line tells you — where the binary is supposed to live — is thrown
away before the check.

There is no `PATH` search either, so `cargo build --release` can never be found
unless `cargo` is in one of the five directories.

## Patch (verified)

Keep the absolute path when the command has one, search `PATH` for bare names, and
factor the directory join so the two callers cannot drift:

```diff
--- a/src/check.rs
+++ b/src/check.rs
     } else {
-        str::basename(first)
+        first
     };
     if name.is_empty() {
         None
-    } else {
+    } else if name.contains(&b'/') {
+        // Keep the absolute path: the command names where the binary lives.
         Some(name)
+    } else {
+        Some(str::basename(name))
+    }
+}
+
+fn exists_in(dir: &[u8], name: &[u8]) -> bool {
+    let mut path = Vec::with_capacity(dir.len() + name.len() + 1);
+    path.extend_from_slice(dir);
+    if !dir.ends_with(b"/") {
+        path.push(b'/');
     }
+    path.extend_from_slice(name);
+    sys::access(&path, 1)
 }

 fn exists(name: &[u8]) -> bool {
     if name.contains(&b'/') {
         return sys::access(name, 1);
     }
+    if let Some(path) = std::env::var_os("PATH") {
+        use std::os::unix::ffi::OsStrExt;
+        for dir in path.as_os_str().as_bytes().split(|b| *b == b':') {
+            if !dir.is_empty() && exists_in(dir, name) {
+                return true;
+            }
+        }
+    }
     for dir in [&b"/usr/local/bin"[..], &b"/usr/bin"[..], &b"/bin"[..],
                 &b"/usr/sbin"[..], &b"/sbin"[..]] {
-        let mut path = Vec::with_capacity(dir.len() + name.len());
-        path.extend_from_slice(dir);
-        path.extend_from_slice(name);
-        if sys::access(&path, 1) {
+        if exists_in(dir, name) {
             return true;
         }
     }
     false
 }
```

Verified: `bluetoothd` is no longer in the missing list, and the "missing" label
now prints the path it tested rather than a bare basename:

```
before: missing: bluetoothd  <- /usr/lib/bluetooth/bluetoothd
after:  (not reported)
```

## Second, separate defect in the same output (already tracked as #13 item 13.4)

`check --binaries` exits 0 with 148 of 181 executables missing:

```
$ psgen check --binaries >/dev/null; echo $?
0
```

`src/check.rs` computes the exit code from the denylist, placeholder, control and
empty-command counters only; `missing` is not in the condition:

```rust
if deny_hits + placeholder_hits + control_hits + empty_hits > 0 {
    1
} else {
    0
}
```

This is #13 item 13.4 and is **not** part of this issue; it is listed here only so the
two changes to `check` land together if you take both. The fix for *this* issue
(the misreported paths) is independent of the exit-code decision.

## Test that would have caught it

```python
out = run(["check", "--binaries"]).stdout
for line in out.splitlines():
    if not line.startswith("missing: "):
        continue
    path = line.split("<- ", 1)[1].strip().split()[0]
    if os.access(path, os.X_OK):
        fail(f"check --binaries reported an existing path missing: {path}")
```

That is a pure host-side assertion and needs no fixtures. Add a second check that
`check --binaries` exits 1 when anything is missing, if that behaviour is adopted.

## Environment

`bf80156` built with `cargo 1.99.1`, x86-64, Linux 7.2.11, unprivileged uid 966.
`/usr/lib/bluetooth/bluetoothd` is the specific path that demonstrates it here;
`/usr/lib/systemd/*` and `/usr/lib/postgresql/17/bin/*` show it on any Debian/Arch
host, so it is not a quirk of this cage.
