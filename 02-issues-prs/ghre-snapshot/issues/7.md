## Body

## What happens

`0.0.1` is written out by hand in eight places, and one of them is a *parser*:
`stop` only recognises a pidfile header whose version is exactly `0.0.1`.

```
$ grep -rn '0\.0\.1' --include=*.rs src/      # doctored to show only the version uses
src/cli.rs:141:    "psgen 0.0.1 - realistic Linux process lists, …
src/cli.rs:765:        sys::out(b"psgen 0.0.1\n");
src/cli.rs:781:            sys::out(b"psgen 0.0.1\n");
src/doctor.rs:165:        out.push_str("\"version\":\"0.0.1\",\"ok\":");
src/doctor.rs:222:        out.push_str("psgen 0.0.1 doctor\n");
src/inject.rs:572:    buf.push_str("# psgen 0.0.1 boot ");
src/inject.rs:1149:        if let Some(rest) = line.strip_prefix(b"# psgen 0.0.1 boot ") {
```

Also `.github/release-notes.md:1` and `README.md:40,148`, and
`tests/vm.sh:65` greps for the exact string.

## Why it matters beyond tidiness

`src/inject.rs:1149` is the only place the boot-id guard is armed:

```rust
if let Some(rest) = line.strip_prefix(b"# psgen 0.0.1 boot ") {
    let boot = str::trim(rest).to_vec();
    …
}
if let Some(hb) = &header_boot {
    let cur = util::boot_id();
    if !force && !hb.is_empty() && !cur.is_empty() && *hb != cur {
        sys::err(b"psgen: pidfile is from another boot; use --force to ignore\n");
```

Bump the version to `0.0.2` and the `strip_prefix` silently stops matching, so a
pidfile from before a reboot is no longer detected as stale: `stop` will happily
check identities and signal whatever now owns those PIDs. Failing open is the
wrong direction for the one check that exists to prevent exactly that. The same
`strip_prefix` also breaks `stop` on a pidfile written by an older binary kept
around after an upgrade.
