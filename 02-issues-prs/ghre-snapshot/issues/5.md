## Body

## What happens

A run that ends by `--duration` alone leaves its staging directories on disk.
Nothing removes them, because the injector process is gone by then and the stub
dies on `SIGALRM`.

```
$ rm -rf .psgen-stubs
$ psgen inject -n 3 -s 7 -d 1 --disk 1 --pidfile /tmp/p.pid -q
$ ls -d .psgen-stubs/.psgen-* /tmp/.psgen-*
.psgen-stubs/.psgen-7255-9000-0
/tmp/.psgen-7255-0-0
/tmp/.psgen-7255-1-0
/tmp/.psgen-7255-2-0
$ sleep 2                       # every stub has exited by now
$ ls -d .psgen-stubs/.psgen-* /tmp/.psgen-*   # still there
$ find .psgen-stubs /tmp/.psgen-* -type f | wc -l
4                               # 1 shadow copy (684 kB) + 3 × data.bin (1 MiB)
$ psgen stop --pidfile /tmp/p.pid
stopped 3 processes             # and now they are gone: stop cleans them up
```

So the leak is exactly "a timed run that nobody stops". It matters because:

* the leftover `psgen-stub` copy is a 684 kB artefact of psgen sitting in the
  working directory, named `.psgen-<pid>-9000-0/psgen-stub`, which is the one
  thing `--shadow-dir`/`./.psgen-stubs` exists to contain;
* with `--disk MiB` the leftovers are up to `rows × MiB` of `data.bin` in
  `TMPDIR` (500 rows × 100 MiB = 50 GB), and nothing reclaims it;
* `psgen unit` uses no `--duration`, so this is not the unit's problem — it is
  the `-d` / `--cpu … -d` / one-shot usage that a test harness actually uses.

`--wait` is fine (it removes the temp dirs itself), and `stop` is fine.

## Where it comes from

`src/inject.rs`, `spawn()`: the `# temp` dirs are removed only by
`stop`/`--wait`. `src/stub.rs`, `run()`:

```rust
if cfg.duration > 0 {
    sys::alarm(cfg.duration);
}
```

`cfg.temp` is already in the stub's config (it is the directory `write_disk`
writes into and the bind tier binds through), but nothing uses it on the way
out, and the default `SIGALRM` action does not run any code in the stub.

## Options, in order of how much I would like them

1. **Prune on the next run** (safe, no new code in the stub, no signal handler):
   before spawning, scan the shadow root and `TMPDIR` for `.psgen-<pid>-<idx>-<n>`
   directories whose `<pid>` is no longer alive, are owned by the caller, and
   match the existing `.psgen-digits-digits-digits` shape that `safe_temp_dir()`
   already validates. Reuse that predicate, skip anything that fails it:

   ```rust
   // in prepare(): forget the runs whose injector is gone
   fn prune_staging(roots: &[&Path]) {
       for root in roots {
           for e in std::fs::read_dir(root).into_iter().flatten().flatten() {
               let name = e.file_name();
               let Some(pid) = staging_owner(&name.to_string_lossy()) else { continue };
               if std::path::Path::new(&format!("/proc/{}", pid)).exists() { continue; }
               // same guards as safe_temp_dir(): real dir, ours, matching name
               let _ = std::fs::remove_dir_all(e.path());
           }
       }
   }
   ```

   Cost: one `readdir` per run. Risk: a live run of *another* user with a live
   pid is skipped by the `/proc` check; a recycled PID keeps a stale dir until
   the next run, which is the conservative direction.

2. **Document it** and add the `# temp` paths to the summary line, not just to
   the pidfile, so a `-d` user sees what will be left behind.

3. **Clean up in the stub** when its timer fires. A timer *thread* is the easy
   implementation (sleep, `remove_dir_all(cfg.temp)`, `_exit(0)`), but it adds
   one to `Threads:` in `/proc/PID/status` for every stub, which breaks the
   thread count the tool exists to fake. A `SIGALRM` handler avoids that but
   cannot call `remove_dir_all` (not async-signal-safe). If this route is taken,
   it should be a handler that only `_exit`s and a prune pass (option 1) that
   does the removal, or `signalfd` in an existing thread.

## Reproduce

```
psgen inject -n 3 -s 7 -d 1 --disk 1 --pidfile /tmp/p.pid -q; sleep 2
ls -d .psgen-stubs/.psgen-* /tmp/.psgen-*          # 4 directories
```

## Environment

psgen 0.0.1-beta.1 x86_64-unknown-linux-musl, unprivileged, Linux 7.2.11;
`exe tier shadow` (no mount namespaces in the cage), `TMPDIR=/tmp`.

One more data point for the "prune on the next run" option (which I agree is the right one): the staging name already carries the injector PID (`.psgen-<pid>-<idx>-<n>`), and `safe_temp_dir()` already validates the shape, so the prune is `readdir` + a `/proc/<pid>` existence check + the existing predicate. No new state, no signal handler in the stub, and it cannot touch a live run of another user because the `/proc` check fails.

The thread-based cleanup is the option to avoid: a timer thread would add one to `Threads:` in `/proc/PID/status`, which is the exact number this tool exists to fake.

Not addressed on the branch `qa/verified-fixes` in `Nemo-010/psgen` — the summary now lists the temp dirs when no pidfile is written, which is only option 2 of your three.
