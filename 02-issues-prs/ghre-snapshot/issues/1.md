## Body

## What happens

A pidfile that psgen itself wrote is then refused:

```
$ : > /tmp/p.pid
$ psgen inject -n 1 --pidfile /tmp/p.pid -q     # rc=0, file written
$ psgen inject -n 1 --pidfile /tmp/p.pid -q
psgen: cannot write the pidfile /tmp/p.pid: the path is not an empty file or a psgen pidfile; use /tmp/psgen-tmp/psgen-pids.txt instead
$ echo $?
2
```

README, *Pidfile and stop*: "An existing target must be absent, empty or a psgen
pidfile". The third case never works. The same defect shows up twice more:

```
$ psgen doctor --pidfile /tmp/p.pid
pidfile	DENY	/tmp/p.pid            # a file psgen just wrote itself

$ psgen unit > /etc/systemd/system/psgen.service   # ExecStart has --pidfile /run/psgen.pid
# systemctl start psgen   → ok (file absent)
# systemctl stop psgen    → ExecStop runs, the pidfile stays on disk
# systemctl start psgen   → fails, exit 2, "not an empty file or a psgen pidfile"
```

So the unit the tool prints cannot be restarted, which is the one thing a
`Type=oneshot` + `RemainAfterExit=yes` unit is expected to do.

## Why

`src/probe.rs`, `pidfile_target_ok()`:

```rust
let mut buf = [0u8; 16];
match sys::read_file(path, &mut buf) {
    Some(n) => n >= 9 && &buf[..9] == b"# psgen ",   // <- line 366
    None => false,
}
```

`b"# psgen "` is eight bytes. `&buf[..9]` is nine, and a slice comparison tests
the length first, so the expression is false for every input. (Verified
directly: `&buf[..8] == b"# psgen "` is `true`, `&buf[..9] == b"# psgen "` is
`false`.) Only the `NotFound` and `len == 0` early returns can be true today.

`write_pidfile()` calls the same predicate, so even without the preflight a
second run would fail to write ("the pidfile was not written", exit 1).

## Patch

```diff
--- a/src/probe.rs
+++ b/src/probe.rs
@@ -358,10 +358,15 @@
     if meta.len() == 0 {
         return true;
     }
+    const HEADER: &[u8] = b"# psgen ";
     let mut buf = [0u8; 16];
     match sys::read_file(path, &mut buf) {
-        Some(n) => n >= 9 && &buf[..9] == b"# psgen ",
+        // The header is eight bytes: comparing nine bytes of the buffer with
+        // an eight-byte literal is always false, which made every non-empty
+        // pidfile look foreign.
+        Some(n) => n >= HEADER.len() && &buf[..HEADER.len()] == HEADER,
         None => false,
     }
 }
```

Verified: built with `cargo build --release`; the three-step repro above now
succeeds on the second and third run, `psgen doctor --pidfile` on a psgen
pidfile reports `ALLOW`, and the repository's own `tests/smoke.sh`
(`invariants: ok`) still passes.

## Test that would have caught it

`tests/invariants.py`, `check_stop()` never reuses a pidfile. Two lines are
enough:

```python
# the same path twice: the second run must accept the file the first wrote
inject_and_check(["inject", "-n", "1", "--no-mem", "--no-tty", "--no-threads"], tmp, 1)
stop_pidfile(pidfile)          # does not unlink
inject_and_check(["inject", "-n", "1", "--no-mem", "--no-tty", "--no-threads"], tmp, 1)
```

`check_stop()` currently creates a fresh file per case, and `check_doctor()`
only probes a writable path that does not exist, so neither notices.

## Environment

psgen 0.0.1-beta.1, x86_64-unknown-linux-musl, unprivileged, Linux 7.2.11.
Not root-specific; the pidfile logic is the same for any caller.

## Comments

### Nemo-010 - 2026-11-09T03:33:18Z

Re-verified against a clean build of `bf80156` (cargo 1.99.1, x86-64, Linux 7.2.11, unprivileged), and the same predicate is also what makes the printed systemd unit non-restartable — filed separately as #27.

```
$ : > /tmp/r1.pid
$ psgen inject -n 1 --pidfile /tmp/r1.pid -q          # rc 0, file written
$ psgen stop --pidfile /tmp/r1.pid
stopped 1 processes
$ psgen inject -n 1 --pidfile /tmp/r1.pid -q
psgen: cannot write the pidfile /tmp/r1.pid: the path is not an empty file or a psgen pidfile; use /tmp/psgen-pids.txt instead
$ echo $?
2
$ psgen doctor --pidfile /tmp/r1.pid
pidfile	DENY	/tmp/r1.pid
```

`&buf[..9] == b"# psgen "` is false for every input, so only the absent-file and empty-file paths can ever succeed.

With the eight-byte comparison the second run is rc 0 and `doctor` reports `pidfile ALLOW /tmp/r1.pid`. `/tmp/r1.pid` is byte-identical between the two runs (`# psgen 0.0.1 boot <uuid>` then `pid<TAB>starttime<TAB>comm`), so there is nothing else standing in the way.

A fix is staged on the branch `qa/verified-fixes` in `Nemo-010/psgen`, with a regression check that runs `inject` twice against the same path.
