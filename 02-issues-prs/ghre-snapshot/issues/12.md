## What happens

`--dry-run` is documented as "print what would be spawned", and it is the only way
to test a plan without touching the process table — which makes it the natural
seam for CI, for a `--table`-less preview, and for the "did my flags do what I
think" question. Today it prints two columns and nothing else:

```
$ psgen inject -n 2 -s 3 --dry-run
user	nginx: master process /usr/sbin/nginx -g daemon on; master_process on;
user	nginx: cache manager process
psgen: user switching needs root; running as user (use sudo, --elevate, or --no-root)
psgen: reduced capability: pty=no (run `psgen doctor` for the errno)
```

So the flags this issue is about are invisible in a dry run:

* the exe tier that will actually be used (`bind` / `shadow` / `proc-self`) —
  only printed on a real run, and it is the single most environment-dependent
  decision the tool makes;
* `--shadow-dir` / `--no-exe` / `--no-root`, which change that tier;
* per-row VSZ/RSS after `--mem-target`, `--mem-cap`, `--phys-cap` scaling and the
  `RLIMIT_FSIZE` clamp;
* per-row CPU after `--cpu`, and whether `--busy` put the row on the busy path;
* whether the row would get a pty, a second thread, its own temp dir (bind tier
  with a missing path, or `--disk`), and the parent/child shape;
* the planned physical cost estimate and whether it was scaled;
* `--disk` totals (`rows × MiB`) before anything is written.

Everything needed is already computed: `inject::prepare()` fills a `Prep` with
`tier`, `shadow_root`, `warnings`, `phys_estimate_kb`, `phys_scale` and mutates
`rows` in place (users resolved, mem planned, flags adjusted), and `spawn()` is
the only thing that consumes it.

## What I would print

Keep the current two columns as the default so nothing breaks, and add a plan
behind an explicit switch, because the existing output is used by
`bench/measure.py` (`dry = run(["inject", …, "--dry-run"])`, split on `\t`):

```
$ psgen inject -n 2 -s 3 --dry-run --plan
tier shadow from /workspace/.psgen-stubs   mem on, tty no, threads on, busy off
plan: 2 stubs, 1 root; rss 35 MiB shared, ~35 MiB physical (budget 2903 MiB)
row 0 root  user  vsz 15036  rss 8576  cpu 0.0  tty -  threads 0  exe /usr/sbin/nginx
row 1 child user  vsz 17000  rss 5336  cpu 0.0  tty -  threads 0  exe /usr/sbin/nginx
                                        parent row 0
```

(`--plan` or `--verbose` — the name matters less than the content; `--dry-run`
alone should keep its exact current format.)

Implementation sketch, in the `args.dry_run` branch of `cli.rs::run`, after
`print_notes(&prep)`:

```rust
if args.plan {
    let mut out = Buf::new();
    out.push_str("tier ");
    out.push_str(prep.tier.name());
    if let Some(d) = &prep.shadow_root {
        out.push_str(" from ");
        out.push_bytes(d);
    }
    out.push_str("\nplan: ");
    out.push_u64(rows.len() as u64);
    out.push_str(" stubs, ");
    out.push_u64(rows.iter().filter(|p| p.parent.is_none()).count() as u64);
    out.push_str(" roots; ...\n");
    for (i, p) in rows.iter().enumerate() {
        // user, vsz, rss, cpu, tty (y/n), threads, template_exe(&CORPUS[p.tmpl])
    }
    sys::out(out.as_bytes());
}
```

## Bonus, same seam: a `--json` plan

`psgen inject --dry-run --json` would make the plan consumable (one object per
row), which is what a CI check actually wants; see #8 for the same argument about
`doctor --json`. Not required for this issue.

## Verified behaviour today

```
$ psgen inject -n 4 -s 7 --dry-run --mem-target 8192 --cpu 40 --no-root
user	/usr/sbin/cron -f
user	nginx: master process /usr/sbin/nginx -g daemon on; master_process on;
user	nginx: worker process
user	nginx: worker process
psgen: --no-root disables user switching and the bind tier; --shadow-dir still selects a shadow copy
psgen: reduced capability: pty=no (run `psgen doctor` for the errno)
```

Nothing in the output says the tier became `proc-self`, that RSS will be 8192 KiB,
that CPU will be 40 %, or that `--no-root` overrode anything but the two things
the warning names.

## Environment

psgen 0.0.1-beta.1 x86_64-unknown-linux-musl, unprivileged, Linux 7.2.11.
